# Online Session reclamation plan

Authority: swxtchio/swx-opencode#353, its [published producer contract](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6537686549), and the [round-two correction](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6541481027), together with the task brief's “Need” and “Constraints.” This plan resolves the implementation boundary; the shipped CLI and its output remain authoritative for behavior.

The proof-preparation and preflight contract is further clarified by the [round-five correction](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6553050249) and [round-six correction](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6555341679).

## Plan

- Add `opencode db prune --online` as a separate owner from the existing offline prune and retire paths.
- Require an explicit database target and explicit Session IDs for online mutation. Keep the existing missing-directory, activity, storage-ownership, parent, cascade, writer and work-state protections.
- Keep inventory scoped to the requested IDs and avoid whole-history payload materialization or hashing. Prove work state and activity with Session/aggregate-scoped indexes; activity uses a scoped maximum rather than requiring a new whole-source ordering index. Query-plan checks reject whole-table scans, temporary sorts and materialized queue-ID lists. Revalidate monotonic per-table high-water fences (rowid, sequence, or the verified keyset tuple) under each write transaction. Check cross-Session Part references by stable Message ID in the same locked batch before any Message delete can cascade. Page Message and event deletion by `message_session_time_created_id_idx` and `event_aggregate_seq_idx`.
- Reclaim only when the existing store reports incremental auto-vacuum support. Use positive page-bounded vacuum steps with passive checkpoints between them, outside deletion transactions; recheck the caller’s free-space reserve before every mutating step.
- Emit one JSON result on stdout, keep diagnostics on stderr, and preserve committed progress, completed and remaining Sessions, protected residue, outstanding checkpoint/freelist work, per-batch lock duration, and separate page and filesystem-allocation measurements across failures and retries.
- The producer contract is published in [issue #353](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6537686549), with its [limit clarification](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6537694254) and [round-two correction](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6541481027); implementation guidance is recorded in `docs/dead-session-retirement.md` and `CHANGESET.md`. Producer-driven CLI tests cover >10k-row adversarially ordered histories, indexed-proof plan refusals, reader-pinned reclaim debt, Session-row byte/capacity limits, bounded partial work, late cross-Session Parts and live-writer progress.

## Round-four correction sequence

The round-four corrections preserve the no-validation-row-cap contract and make existing-store proof preparation live-safe:

1. Keep whole-table source-index construction out of the live reclamation path. Existing per-Session indexes, proof-table indexes and triggers support it; no source index is rebuilt to reclaim an existing store.
2. Make online `--apply` the only existing-store proof preparation path. It advances cross-Session Part scope, stable queue-alias ownership and writer-lifetime maps in transactions capped at 128 rows, with at most 128 proof transactions per invocation (a fixed 16,384-source-row ceiling, not caller-configurable). `proofPreparation` reports completed batches, rows and remaining proofs. An incomplete, busy, or unavailable proof refusal exits 1, deletes no Sessions, and is retried with the same explicit apply scope after progress, contention, or state is addressed. Other database holders stay live between batches.
3. Key alias ownership by `(item_id, alias_id)` and cross-Session Part proofs by stable `part.id` and Message IDs; never persist an implicit Part ROWID as a backfill cursor. Inventory uses the completed maps; each delete transaction rechecks late external Part references before a Message can cascade.
4. Keep the historical per-Session `event_aggregate_writer` census paged outside each `BEGIN IMMEDIATE` delete batch. Under the lock, rescan current process holders and verify their `(pid, boot_id, start_ticks)` registrations by primary-key lookup. Do not replay historical writer ownership under the lock; revalidate Session writes with the captured event-sequence/owner and per-table high-water fences.

## Round-five contract clarification

The fixed proof-preparation bound is 128 source rows per proof transaction and 128 proof transactions per invocation (at most 16,384 source rows); no CLI option changes it. A read-only capacity and holder-inspection preflight runs before proof writes; if it refuses, `proofPreparation` shows zero batches and rows and the proof state is unchanged. Reserve preflight reports `free-space-reserve-would-be-violated` or `free-space-measurement-unavailable`; the reserve is rechecked before every proof transaction. A mid-pass reserve refusal reports `free-space-reserve-would-be-violated`, rolls back that page, and preserves earlier committed progress. Incomplete, busy, and unavailable proof state refuses deletion with exit 1. Retry the same explicit online apply scope to resume; proof progress is reported separately from deleted-row `committed` status. See `docs/dead-session-retirement.md` for the exact reason strings and JSON shape. The in-lock current-holder identity check remains; the historical per-Session writer census is outside the lock and locked writes are guarded by event-sequence and row fences.

## Round-six trigger and preflight correction

The Message cross-update trigger uses only migrated `part_message_id_id_idx`, not fresh-schema-only `part_message_id_session_idx`; existing stores need no source-index build. An `unregistered-database-holder:<pid>` is deferred only while `event-writer-lifetimes` backfill is incomplete. Apply completes that census, reruns holder and selected-Session writer checks, and refuses deletion if a holder remains unregistered, preserving proof progress. Capacity and holder preflight refusals happen before proof writes; a mid-pass reserve refusal rolls back only that page and preserves earlier proof batches. Retention treats proof tables as structural metadata, preserving maps while their source rows remain and relying on source lifecycle triggers to clear them on deletion. See the [round-six contract correction](https://github.com/swxtchio/swx-opencode/issues/353#issuecomment-6555341679).

Each correction lands with a producer-driven regression in its own commit. After all required findings pass the complete prune suite, Core/OpenCode typechecks, and lint/format checks, update and push the draft PR for review.
