# Synthetic grouped-delivery checkpoint

`checkpoint.json` is generated by the real durable queue's admission/promotion and normal `MessageV2.get` read path, not handwritten output or live session data. The test uses its existing synthetic User preparation callback and real `Session.updateMessage`/`updatePart` writers. Production grouping, reservation, commit, projection, consume and reads are exercised. Recipient model/effort selection has separate real-provider tests; the fixture's synthetic receiver information does not claim a provider call or completed acknowledgment.

Generation requires a clean committed producer checkout. From `packages/opencode`, with an existing workspace install:

```sh
TMPDIR="$PWD/../../.latency/tmp" OPENCODE_WRITE_GROUPED_FIXTURE=1 \
  bun test ./test/session/queue-dispatch.test.ts \
  --test-name-pattern 'emits grouped consumer checkpoint' --timeout 30000
```

The fixture records the exact producer SHA, generator/test and runtime. Synthetic input identities are fixed; session/queue/message/part IDs and admission timestamps are real captured values. Regeneration therefore produces different bytes and requires a new committed capture and review. The producer SHA is the committed generation checkpoint, not a self-referential claim about the later fixture-artifact commit.

Each scenario includes actual caller inputs, admitted originals and their encoded queued inputs, the pending response before promotion, full returned message parts/metadata, the same read after normal consume, all aggregate/ignored witnesses and actual model-message conversion. Peer request/info framing, accepted transport aliases before promotion and after consume, repeated/distinct automation episodes, unknown-duty long heartbeat references and an identified individual input are included. Automation text is historical provenance, never a fresh condition measurement; Firstmate owns remeasurement and pacing.

Compare the original caller's queued-input projection with `metadata.sessionQueue.constituents[].input`. Admission-only `sessionID`, `noReply` and `delivery` are outside that input projection; session and delivery remain on each constituent. Literal parts/envelopes, optional supplied messageID, agent/model/variant settings and original admission time remain unchanged. The test asserts actual encoded input equality rather than treating metadata presence as acknowledgment.

One aggregate metadata part lists all originals. Ignored synthetic parts list singleton originals: original transport, accepted retry aliases and validated peer identity point at the same original queue ID and outer message. Deduplicate by `(sessionID, constituent.id)` after exact original-input/identity validation. These are not extra deliveries, tasks or acknowledgments. The fixture also demonstrates their exclusion from model input and persistence after consume. Conflicting identity reuse is covered by the queue-dispatch regression cases.

No new receipt API, producer scheduler, live store operation or publication approval is introduced. The committed producer and capture must receive independent review before the consumer pin is called reviewed or published.

For retry comparability, read `admitLocked`, `constituentIDs`, `rememberAliases` and `sameQueuedInput` in the pinned queue source alongside the capture's `retryCalls` / `afterConsumeRetryCalls` / `returnedAfterRetry`. The canonical encoded input and the accepted transport alias are distinct identity evidence; the original input is not rewritten to make a later transport ID look original. An alias witness does not add work or an acknowledgment. The individual scenario exercises the same ignored witness owner without forcing an aggregate or changing the native displayed text.
